- Shared accessor (module.exports): trust-boundary defenses + return contract (explicit columns, not SELECT *) belong IN the function; every caller inherits what it omits.
- Undoing a resource created earlier in a pipeline: put ONE reaper/backstop at the resource's lifecycle boundary, not an undo line per failure branch — per-branch cleanup misses the paths you didn't enumerate (crashes, user-denied prompts, future branches).
- Distributing a hook to multiple bundles: duplicate only the part that differs (the prompt/data), keep the executable single-sourced where possible, and never let variant payloads collide at one hardcoded flat runtime path (last-writer-wins hides drift).
- Governance artifact (hook/linter/CI gate) should REFERENCE the doc it enforces, never restate it — rule text living in both enforcer and doc makes the enforcer a second source of truth that drifts.
- "De-duplicate the spec" isn't done until every copy is collapsed to one authority — fixing only the files in this turn's diff while N sibling files still restate it relocates the drift; grep the whole doc set for the restated text.
- When a fix opts a call site into a shared component's EXISTING controlled-mode API (not a new prop), blast radius is zero by construction: confirm the shared file is untouched in the diff and siblings pass no controlling prop, then stop; don't re-litigate the shared component.
- Governance hook switching from inlining a doc to referencing it: the reference must be a PURE bootstrap ("read X and follow it"), any procedural text kept "so the host knows what to do first" re-forks the spec — the doc it points to is where the procedure lives.
- When a reviewer says 'use a token instead of a px literal,' grep the theme scale to confirm a matching token exists before treating the literal as debt — Chakra w/h read the sizes scale (not the 8px space scale), so a numeric swap can silently mean a different pixel value.
- Hook forked across install layouts where the ONLY delta is a data-file path: don't ship a cleaner copy — REMOVE the delta (try-then-fallback, or derive from $0/env) so the executable is byte-identical everywhere. A hardcoded-but-divergent path also wants a loud-fail or install check, since fail-safe `|| exit 0` turns a misinstall into a silent no-op.
- A sync->async refetch fix trades a silent-wrong-value bug for a transient-wrong-value flash; if render un-gates on a sibling signal (not the awaited promise) the flash survives — durable fix is to bootstrap init with the complete user, not patch the post-init re-key.
- For a follow-up that only opts a call site into an existing observability API (logging a previously-unhandled rejection), the correctness question collapses to "does the failure change behavior?" — if the mutation already applied its effect synchronously and the failing path is a background refetch the SDK re-drives, log-and-move-on beats silent-swallow and retry; blast radius zero.
- A comment that names the wrong alternative it exists to prevent ("Async not Sync") is worth more than one that only describes current behavior — the negation stops a future edit from regressing.
- A cross-reference in a comment is a dependency — when the referenced passage is reworded or removed, delete the pointer in the same breath, or it rots into a dangling reference.
- A rename that migrates state dirs must also delete the OLD runtime dirs, not only the referenced ones — grep every writer AND `ls` the runtime-dir siblings; an orphaned empty dir passes every reference check but is still drift.
- When a trim drops a comment's altitude-cue (this-is-the-secondary-not-authoritative control) while keeping the regression-negation, it's a soft loss not a blocker — but a one-line pointer to where the authoritative control lives is cheap insurance and survives the minimize-comments rule.
- When judging a comment trim, grep the callers before trusting the old comment — a comment can be verbose AND stale; confirming the described usage against real call sites can flip a suspected loss into a correctness gain (e.g. a "used by web + mobile proxy" note on a method that only the web path calls).
- A caller-path cue in a method-level comment ("web sessionLogin path") is redundant when the single call site is itself commented AND a differently-signed sibling names the other path — signatures + call-site comment carry the disambiguation the doc-comment claimed.

- A "dev-only, no-auth" sibling entrypoint earns its keep only if its danger is contained by code, not prose — one guard at its startup boundary (refuse non-local targets) beats trusting every future operator to read the README.

- "pure extraction, logic byte-identical" warrants a char-level diff of the moved expression before waving it through — a silently-added regex flag (/i) slipped in under that label; benign here, but the claim is what a reviewer trusts.
- When a refactor's job IS to fix "no input validation," the moved logic is byte-identical but there will be one legitimately-new gate — char-diff the moved expressions to wave those through, and separately confirm the single new behavior matches the named scope item.
- When a review flags a "missing" control (throttle/guard/validation), run `git log -S '<token>' --all` FIRST -- the control may have been removed deliberately to work around a live bug. Re-adding the same thing repeats the mistake; recommend the safe variant the history converged on.

- A pre-existing sibling using px literals for an element's intrinsic dimensions (icon w/h) and a sub-token alignment nudge is a legitimate exception to a token-only spacing rule — flag it once as informational, don't hold the verdict on it when the diff is mirroring established convention.

- When a change swaps the consumer of a screen/route (route now renders a new component), grep the OLD component AND its exclusive hooks/service/constants for remaining referrers — a migration that only edits the entry point routinely orphans a whole downstream path AND any security gate it carried (here the register-flow swap dropped a Twilio OTP step-up), left silently dead in the diff.

- When a build-toolchain bump lands (compileSdk / Kotlin / stdlib forces), re-read EVERY existing `force`/version comment in the same session — stale pins + contradictory comments from a prior attempt survive as config that compiles-by-luck, not design. A whole-app compileSdk/Kotlin bump to satisfy one vendor SDK is a disproportionate blast radius; prefer pinning an older SDK version or a compiler flag (-Xskip-metadata-version-check) over recompiling every module on an untested toolchain.

- In an Expo CNG app, `/ios/` and `/android/` are gitignored generated dirs: ANY native hand-edit (pbxproj, SPM ref, MainApplication/AppDelegate registration, Swift/Kotlin bridge sources) is ephemeral — `expo prebuild --clean` wipes it. Grep .gitignore + `git ls-files` FIRST; durable home is a `plugins/with*.js` config plugin. "Matches the sibling platform" does NOT rescue durability when the sibling is equally ephemeral.

- On an explicitly-disposable/demo branch, judge by containment not cleanliness — dead code + a --no-verify lint bypass are expected debt; the finding that keeps its weight is whether the throwaway edit is wired into a PRODUCTION-SHARED file (real merge/cherry-pick blast radius) vs an isolated harness.
- When a rewrite replaces a proven-working approach with a heavier one, the plan must justify the trade vs the incumbent explicitly — maintenance surface + blast radius are design decisions, not implementation details.

- When a diff's whole purpose is to move a sensitive artifact across a trust boundary (server→client), grep the artifact's PRODUCER for comments asserting the OLD containment ("never reaches the client", "server-side only") — the reassurance the codebase gave itself under the old design becomes an active lie under the new one, sitting exactly on the line a security reviewer trusts most.

- When a fix promotes a "staging"/soft field (e.g. userMetadata.unverifiedPhoneNumber) into its canonical column from a NEW call site, check the original graduation path for validations AND post-graduation guards the new path skips — the lazy correct move is to route through that existing path, not re-add its checks.

- A client-side UI visibility gate must mirror the SERVER guards EXACT condition — else "show the button" and "allow the action" drift. (e.g. a web gate requiring a VERIFIED phone while the backend guard accepted any phone on file; fix = match the backend condition exactly.)

- "Wire config value X in like sibling Y" is usually a 4-file contract, not 2: local template + schema validation + EVERY deploy buildspec (normal AND hotfix). If the deployed env file is regenerated from the buildspec's parameter args alone, the local template is never read in deployed envs — omitting a buildspec makes the change a silent no-op everywhere but local. Check the sibling's OWN commit (`git log -- <buildspec/deploy files>`) for the full file set before judging "matches siblings" complete.

- When a flag is threaded by mutating a shared in-flight object (`decodedToken.foo = ...` then passed onward), confirm it's the SAME object reference passed synchronously in one call chain — not re-decoded/cached/round-tripped between mutation and read — before ruling out a "mutation gets lost" bug.

- That multi-file config contract only becomes a LIVE gap once a reader branches on the value at runtime — a schema-only entry for a genuinely unconsumed key (grep-confirmed no reader) is inert scaffolding, not incomplete wire-up; still flag it so the schema's presence isn't mistaken for "already provisioned."
