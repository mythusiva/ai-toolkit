- [payment-provider-service] SQS event handlers (BaseEventReaderHandler → sqs-consumer) deliberately fire-and-forget the service call with a dangling `.catch()`, so throwing inside the service NEVER triggers SQS redelivery — retry/durability for payouts comes from the Cron scheduler + rotating DB `uuid` idempotency key, not the queue. Don't assume "throw in handler ⇒ SQS retry" here; log-level swaps in that catch can't drop a message.
