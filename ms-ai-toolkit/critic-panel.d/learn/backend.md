- In orchestration, HttpException throws MUST use a structured payload `{ messageCode: ErrorCode.X, message }` (existing enum member), never a bare string — grep sibling services (biometric.auth.service) for the shape before passing a controller's `throw new XException('str')`.
- orchestration has no global ValidationPipe and class-transformer isn't installed, so DTO decorators are inert AND you cannot "just add @UsePipes(ValidationPipe)" (it would crash at runtime / need a new dep + gateway-wide blast radius) — the conventional fix is explicit validation in the SERVICE layer, not the controller.
- Thin-controller check: if a new controller inlines validation/business logic while its sibling family (biometric) delegates to a service, flag "logic belongs in a *.service.ts" — the module's own split is the rulebook.
- orchestration throttling is opt-in per route (no global APP_GUARD throttler), and its custom ThrottlerStorage does NOT use the same time unit as the decorator. Read the storage implementation before recommending any `@Throttle` override, and prefer the module default via `@UseGuards(IpThrottleGuard)` with no override.
- When a plan asserts a security invariant in prose ("service X never holds secret Y"), diff it against every code sample in the doc — code samples and prose drift independently, and the code is what ships.

- When a diff deletes the one call that cryptographically verified client-supplied data against a third-party IdP (e.g. a WebAuthn "finish" ceremony call), check whether the surviving mutation still has ANY server-side proof of authenticity — moving an OTP/step-up gate earlier doesn't cover a later mutation that persists client input with no verification of its own.
